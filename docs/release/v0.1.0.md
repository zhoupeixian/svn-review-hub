# v0.1.0 — 首个 GitHub 版本草稿

本次整理现有门户功能与开发验证流程，版本号沿用 `package.json` 的 `0.1.0`。历史 1.0 / 1.1 设计稿名称不代表已经发布过相应 GitHub 版本。

## 功能范围

- 多项目目录、项目切换、审查日志搜索与筛选、Revision 和问题详情。
- P1/P2/P3 结构化问题计数、状态与处理说明、并发版本检查和事件历史。
- 项目内手工导入与自动同步、重复导入保留问题处理记录、同步健康指标。
- 日志归档预览与确认、恢复、只读归档、原文及导出。
- 全站项目管理、项目独立同步密钥、启停与删除、管理操作审计。
- 兼容旧 ZHERP 路由，保留跨项目隔离；普通读取不依赖旧同步密钥迁移成功。

## 开发与维护

- Linux Node.js 22 / 24、Windows Node.js 24 的测试、TypeScript、lint 与生产构建 CI。
- 可重复执行的测试分流、JUnit 报告、通过 CI 后创建 Release 草稿的手动流程。
- Dependabot 定期提出 npm / GitHub Actions 更新，附带 Issue 和 PR 模板。

## 使用与限制

- 需要 Sites 登录环境、Cloudflare Workers、D1 和 R2；不包含独立账号密码登录或通用容器部署方案。
- 这是源码版本草稿，不执行生产部署、数据库迁移或历史日志重导入，也不代表已通过生产浏览器验收。
- 匿名协作事件不具备可靠操作者身份；上线前需配置独立服务端密钥并核对管理员首次登记行为。
- 创建草稿前会运行 CI，但 CI 不等于依赖安全审计；公开发布前仍须检查未解决的依赖告警。
- 仓库尚未声明开源许可证。源码发布不能替代授权决策。
