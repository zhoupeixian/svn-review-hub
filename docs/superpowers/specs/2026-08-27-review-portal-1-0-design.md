# ZHERP SVN 审查日志站 1.0 设计

## 目标与边界

将当前“审查日志阅读器”升级为团队可长期使用的审查协作库：开发人员能够查阅当前审查、匿名更新问题处理进度；管理员能够导入、归档、恢复和批量归档日志；旧日志及其问题仍可检索，但不会干扰首页的当前风险判断。

1.0 采用“公开阅读、匿名协作、管理员归档”的模型：不新增团队成员账号、角色层级、任务指派或个人待办。匿名协作无法可靠识别操作者，这是有意接受的边界；每次变更仍以不可覆盖的时间线保留发生时间、前后状态与处理说明。

## 已确认规则

- 问题原始标题、风险级别、关联 Revision 和审查详情只读，任何协作者都不能修改或删除。
- 协作者只能修改问题状态和处理说明，均不要求登录；所有状态均可再次修改。
- 固定状态为：待处理、待确认、已解决、误判、设计如此、暂不处理。
- 管理员可在任何时间单份或批量归档日志。归档仅改变可见范围，不会关闭、删除或改写问题。
- 首页、首页统计和当前问题总览只计算未归档日志；归档日志与其问题只在归档库中出现。
- 管理员继续使用现有管理入口；不改变当前自动同步、手工上传或原始 Markdown 保存方式。

## 体验结构

### 1. 当前审查首页

首页只展示未归档日志，首屏包含当前日志数、待处理/待确认问题数和 P1/P2 风险数。风险卡片可直接形成筛选条件。日志列表采用服务端游标分页，默认每页 20 条；点击“加载更多”追加下一页，不读取 Markdown 原文。

### 2. 当前问题总览

新增独立的跨日志问题列表，默认显示未归档日志中的待处理和待确认问题。支持按状态、风险级别、审查日期、Revision、提交人和关键词筛选，并提供可复制的 URL 查询条件。结果直接链接到日志详情中对应的问题。

### 3. 审查日志详情

日志详情保留现有原始 Markdown、Revision 和结构化问题。每个问题新增状态徽标、最新处理说明和“更新处理进度”入口。提交后在问题下追加一条时间线记录；页面以服务端返回结果刷新当前状态，失败时明确提示且不伪造成功状态。

### 4. 归档库

归档库是独立页面，采用同样的游标分页与服务端检索。可查询归档日志及其问题的日期、风险、状态、Revision、提交人和关键词；可打开详情、查看问题时间线，并由管理员恢复到当前审查区。

### 5. 管理页

管理页新增当前日志的多选和“按筛选结果归档”。批量操作前必须显示日志数、问题数和未关闭问题数，并要求确认。归档与恢复均返回明确结果；无权访问者不显示管理操作。

## 数据模型与导入规则

### 日志

`review_logs` 增加 `archived_at`（空值表示当前日志）。查询按此字段区分当前区和归档区，并保留日期与 ID 的复合游标索引。

### 问题与时间线

`review_issues` 增加：

- `issue_key`：由风险级别、规范化标题和关联 Revision 生成的稳定指纹；同一日志重复同步时用于识别同一问题。
- `status`：当前状态，旧数据回填为“待处理”。
- `status_note`、`status_updated_at`：当前展示用的最新处理说明与更新时间。
- `source_current`：当前导入版本仍存在该问题时为真。

`issue_key` 在同一日志内唯一；为 `review_logs(archived_at, log_date, id)`、`review_issues(status, source_current, review_id)` 和 `review_issue_events(issue_id, created_at)` 建立查询索引，以支撑当前区、归档区和时间线的固定成本读取。

新增 `review_issue_events`，每次协作更新追加 `from_status`、`to_status`、`note`、`created_at`。不保存操作者，也不提供删除或编辑历史记录的接口。

自动同步或手工重传同一 `source_key` 时，解析结果通过 `issue_key` 对齐：仍存在的问题保留协作状态与时间线；新出现的问题默认“待处理”；新版本中已不再存在的问题保留历史但标记为非当前，不进入当前问题总览。原始 Markdown 仍按现有方式写入 R2。

### 检索

建立 D1 的全文检索索引，覆盖日志摘要、Revision、提交人、提交说明、问题标题、问题详情和最新处理说明。状态、归档状态、风险级别和日期使用普通索引过滤；全文检索仅返回 ID，再按游标读取列表摘要。详情页才读取单份 R2 Markdown。

## API 与匿名协作安全

- `GET /api/reviews`：支持 `scope=active|archived`、日期、风险、状态、关键词和游标；只返回列表摘要。
- `GET /api/issues`：为当前问题总览与归档问题检索提供分页结果。
- `PATCH /api/issues/:id/status`：仅接受固定状态、可选且限长的处理说明与当前版本号；返回最新问题和新增时间线事件。
- `POST /api/reviews/archive`、`POST /api/reviews/restore`：仅管理员可调用；支持显式 ID 或经确认的筛选结果。

匿名更新接口不允许新建、删除或修改原始审查字段。服务端校验状态枚举、说明长度和问题可见范围；对 `CF-Connecting-IP` 做不可逆哈希后实施短窗口频率限制，不保存原始 IP。并发更新通过版本号检测：若页面已过期，返回当前状态和提示，要求刷新后再次提交，避免静默覆盖。

## 1.0 优先功能清单

1. 当前审查首页与风险/状态统计。
2. 跨日志当前问题总览。
3. 问题状态、处理说明与匿名追加式时间线。
4. 单份归档、恢复和归档库。
5. 多选及按筛选结果批量归档。
6. 服务端筛选、全文检索与游标分页加载。
7. 可分享的 URL 查询条件与问题深链接。
8. 导出当前筛选得到的结构化日志或问题 CSV。
9. 自动同步健康信息与解析完整性提示（例如 Revision/问题提取数）。

## 非目标

1.0 不包含任务指派、截止日期、提醒、个人视图、评论提及、企业 SSO、实名审计、人工编辑原始审查结论或 AI 语义检索。这些能力依赖身份体系、外部通知或额外模型服务，应在基础协作数据稳定后单独评估。

## 验证与验收

- 迁移后全部历史日志仍可打开，原始 Markdown、Revision 和问题数量不丢失，旧问题默认“待处理”。
- 状态更新只改变允许字段，并总能在时间线看到新增事件；并发冲突、非法状态、超长说明和超频请求均被正确拒绝。
- 归档后日志及其问题不再出现在首页统计、当前日志列表或当前问题总览；在归档库可检索并可由管理员恢复。
- 批量归档的确认数量与最终变更数量一致；无管理员权限的请求被拒绝。
- 当前区、归档区和问题总览都在数据量增长时保持固定大小的首屏响应；检索、游标和“加载更多”不重复或遗漏结果。
- 同一日志重新同步后，匹配的问题保留已有状态历史；被撤回的问题不会误留在当前问题总览。
- 通过构建、迁移验证、接口测试与浏览器场景测试后再发布。
