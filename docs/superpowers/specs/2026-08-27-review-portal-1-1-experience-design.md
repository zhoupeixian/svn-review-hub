# ZHERP SVN 审查日志站 1.1 体验与导出设计

## 目标与边界

本轮将 1.0 的数据能力打磨为适合团队日常阅读、筛选、分派与跟进的界面。重点是降低长日志、长路径和多条件筛选带来的认知负担；不改变匿名协作与管理员归档权限模型。

确认的目标：

- “导出当前筛选”生成可在 Excel 直接分派和跟进的问题工作表，而非仅供机器处理的 CSV。
- 默认视觉应低饱和、舒适、层级清晰；使用者可在本机切换预置主题。
- 首页统计可作为导航入口；当前日志区域保留轻量查询入口。
- 自动同步和管理员上传都必须从日志正文正确提取审查/跳过提交数。

非目标：本轮不增加身份、问题指派、负责人、截止日期、评论、Excel 导入或改变原始审查内容。

## 信息架构与页面体验

### 全局主题

使用 CSS 设计令牌替代页面中分散的固定颜色。提供三套预置主题：

1. `柔和办公`（默认）：暖白背景、石墨正文、靛青为主要交互色。
2. `工程绿`：保留当前绿色识别，但降低背景与边框饱和度。
3. `夜间专注`：深灰蓝背景、低亮度卡片、保持风险色的可辨性。

主题切换器位于全局页头，采用带文本的按钮/下拉控件，不能只依赖颜色表达当前选择；选择写入 `localStorage`，初始化时读取并设置根元素 `data-theme`。系统不存储主题偏好，不影响其他成员。

所有主题必须定义背景、表面、边框、主/次文字、强调、焦点和 P1/P2/P3 令牌；键盘焦点、悬停、禁用与风险标签在三套主题中都保持可见。

### 首页

- 统计卡成为完整可点击链接：当前日志到 `#history`，待处理/待确认/P1-P2 风险分别跳转问题看板并带对应 URL 筛选条件。
- 在“当前审查日志”标题区域加入轻量检索条：关键词、Revision 和日期三个输入，以及“查询”按钮。提交后跳转 `/issues`，复用已有的服务端筛选参数；不在首页加载或过滤全部问题。
- 日志摘要卡只保留日期、标题、两行内概览、审查提交数、风险标签和单一的“查看日志”动作，避免描述、标签和链接彼此争夺注意力。

### 问题看板与归档筛选

- 使用统一的 `FilterPanel` 视觉与行为模式：卡片头部显示“筛选问题/筛选归档”和结果状态；第一行是状态、严重级别、关键词；日期、作者、Revision 放在可展开的“更多条件”中。
- 输入和选择控件具有独立标签、填充背景、边框、聚焦样式和明确的空值提示；筛选改变采用“应用筛选”而不是每个字符发请求。
- 操作区固定为“应用筛选 / 重置 / 复制链接 / 导出工作表”，显示当前结果数量和最多导出 1,000 条的边界。
- 问题结果使用紧凑卡片：风险徽标与状态徽标、标题、最多两行的处理说明/问题摘要、日志日期/来源/作者等辅助字段、Revision 芯片、明确的“打开原日志”链接。长作者和 Revision 均可断行，不使卡片横向溢出。
- 归档库复用同一筛选面板和摘要卡层次，只保持归档专属的“已归档”标识与恢复入口。

### 审查详情

- 顶部指标使用解析后的 `revisionCount`、`reviewedCount`、`skippedCount`；显示“自动同步/管理员上传”仅作为来源信息，不改变指标。
- 结构化问题卡按“标题与风险 → 关联 Revision → 审查结论（影响、理由、建议）→ 协作状态”排列。详情文本限制适宜行宽，超长路径与代码使用横向滚动的代码块或折叠区，不能撑破页面。
- 状态更新区为视觉独立的协作面板：现状徽标、状态选择、处理说明输入、保存按钮和事件时间线。归档日志仍展示状态/时间线，但保持只读。
- 原始 Markdown 保留在页面底部并可下载，但不与结构化问题竞争首屏注意力。

## 导出工作表契约

`GET /api/issues/export` 保持与问题列表完全相同的过滤参数、当前/归档范围与最多 1,000 条限制，但响应改为 `.xlsx`：

- 文件名：`ZHERP-审查问题-YYYY-MM-DD.xlsx`。
- 工作表名：`问题跟进`。
- 列顺序：严重级别、状态、问题标题、关联 Revision、提交人、日志日期、来源日志、处理说明、最后更新、详情链接。
- 状态导出固定中文标签；空处理说明保持为空；Revision 和长作者字段按文本格式保留，避免 Excel 自动变形。
- 第一行加粗、有主题色背景、冻结；启用自动筛选；列宽按照标题和抽样内容设置上限；标题/说明列自动换行。
- 详情链接写为外部超链接（以站点绝对 URL 为目标）且显示“打开详情”；链接使用安全的 `https`/同站来源构造，不能从数据库原样信任 URL。
- 延续 CSV 的公式注入防护，对任何以空白后 `= + - @` 开头的文本加入文本前缀；不导出原始 Markdown、同步密钥、管理员信息或 IP 数据。

CSV 不再是“导出当前筛选”的默认产物。若保留 CSV 内部工具函数，只能用于测试或兼容旧调用，不在 UI 暴露。

## 数据解析修复

当前解析器只识别“实际审查 N 个、跳过 N 个”。改为识别同义日志范围描述，例如：

- `共 24 个 revision，其中 22 个可审查，2 个按默认规则跳过`
- `共 24 个 revision，实际审查 22 个，跳过 2 个`

优先取明确的“实际审查”值；不存在时取“可审查”值。识别失败才回退为 0，并在同步健康区保留现有异常提示。新增单元测试覆盖两种格式和不存在计数的兼容行为。

## 组件、接口与兼容性

- 新增轻量客户端 `ThemeSwitcher`，仅负责根主题属性和本机偏好。
- 以共享展示组件替代当前问题页、归档页各自的裸标签/控件样式，但保留它们现有请求、筛选参数、游标竞态保护和原生 `<a>` 导航。
- 导出路由通过服务端生成 XLSX 二进制响应；现有 `getIssueExportRows` 仍是唯一导出数据来源，避免列表与导出筛选漂移。
- 仅改变前端展示和导出 MIME/文件名；D1/R2 schema、匿名更新、归档 API 和自动同步鉴权均不改。

## 验收与验证

- 导入题述 2026-08-27 日志后，详情和首页显示 22 个实际审查提交、2 个跳过提交，而非 0/0。
- 导出的 `.xlsx` 能在 Excel 打开，包含一张带筛选和冻结行的“问题跟进”工作表；所有导出行与当前筛选一致，中文状态、可点击详情链接、换行说明和公式前缀防护正确。
- 首页四张统计卡的目标 URL 正确；轻量检索生成正确的 `/issues` 参数且不全量加载问题。
- 当前问题页、归档页、详情页在默认桌面与窄屏视图中不出现输入控件无样式、长内容横向撑破、标题与辅助内容混为一团的情况。
- 三套主题可以切换并刷新后保持；文字、风险标记、输入焦点和禁用态在每套主题中均清晰可见。
- 通过新增/更新的解析、导出、首页导航、主题和 UI 交互测试，以及 `lint`、类型检查、构建与既有测试集。
